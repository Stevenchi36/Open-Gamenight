# Decisions

One line each: what we decided and why. See `PLAN.md` for details. Revisit a decision by editing it here, not by quietly diverging in code.

## Platform
- **Generic platform, Imposter as the first game.** More games are expected; rooms, auth and sockets shouldn't be rewritten per game.
- **Game contract is a pure reducer (`init` / `reduce` / `view`) with effects for timers.** Testable with seeded `rng`/`now`, and the core can guarantee secrecy by only ever sending `view()` output.
- **Player actions (`A`, `reduce`) and timer actions (`T`, `onTimer`) are separate types and handlers.** With one action type, `actionSchema` had to be cast and every timer case had to re-check `actorId === null`; now `actorId` is always a player, clients can't name a timer action, and the compiler keeps the two apart.
- **Core sends only `view()` output, never raw state.** Secret-hiding is enforced in one place for every game, not remembered per game.
- **Generic leak test in core.** Makes "games can't leak secrets" a platform guarantee checked in CI.
- **Secrets are checked two ways: forbidden values and indistinguishable variants.** A string search catches a leaked word but not a leaked association like "this player id is the imposter"; comparing a viewer's view across states that differ only in the secret catches both.
- **Client manifest (`client.ts`) is separate from the server contract (`contract.ts`).** The browser bundle and `vue-tsc` never pull in Express or `node:sqlite` types.
- **Client modules are built with `defineGameClient<View, Settings>`, and the shell passes `room.game.settings` to PlayViews and `needsAction` as a typed `settings`.** `needsAction` used to take `view: unknown` (accepted only through method-syntax bivariance) and play views cast `room.game.settings` by hand; now a mismatch between a game's client and its shared types fails `vue-tsc`.
- **Games import only from `packages/core` and their own folder.** Keeps Imposter usable as the reference example for future contributors.
- **Static game registry (`games/index.ts`), no runtime discovery.** Type-safe, tree-shakeable, and adding a game is one line.
- **A game's id, name, description and player limits (`GameMeta`) are declared once, as `meta` in its `shared/`, and spread into both its server and client modules; a server test checks the two registries match.** They were typed out twice per game and could drift apart.
- **Core protocol messages for room membership; one `action` envelope for game moves.** Core owns who is in the room; games own what happens in play, including game-level permission checks.
- **Host can switch games in the lobby (settings + scores reset).** "Let's play something else" with the same people is the common family-night case.
- **Leave always asks first (lobby button and in-game drawer); the lobby host with others in the room gets Leave or Close room there (alone, leaving closes it anyway). Closing is lobby only.** Leaving gives up the seat and score, and the icon sits next to Invite. Ending the evening shouldn't mean kicking everyone one by one; lobby-only so a tap can't end a game mid-round (Back to lobby first), and on Leave so the compact header gains no button.
- **Switching to a game with a lower player limit keeps everyone; Start is disabled (the server refuses too) and the lobby says how many to remove.** Kicking players automatically would pick who goes; the host may rather switch back or pick another game.
- **Each game ships its own Vue settings component (with shared field components).** Conditional settings are awkward to auto-generate; revisit at 3+ games.
- **The shared settings fields (`SettingSlider`, `SettingSelect`, `SettingToggle`) are registered as global components by the client shell.** Games use them in templates without importing anything outside `packages/core` and their own folder.
- **Reducer building blocks shared across games (presence, `pickConnected`, `nextTurnOrder` + `playerOrderSchema`, scores, vote tallies, `secretBallots`, `DISCONNECT_GRACE_MS`) live in `@wsfg/core/kit`, pure and tested in core.** Every turn- or vote-based game needs them, and a single copy keeps the behaviour (tie rules, rotate order, judge choice) the same across games. The turn engine itself stays per game until a second game shows its shape.
- **Reusable play-view pieces (helpers like `nameOf`/`useCountdown`, and Vuetify components) live in `@wsfg/core/ui` and are imported explicitly.** Games keep importing only from core, and unlike global components they get types and composables. It's browser-only, so core's `tsc` excludes it and the client's `vue-tsc` checks it.
- **Each game's player-facing rules are a `RULES.md` in its folder, loaded by the client module with Vite's `?raw` and rendered with `marked` in a "How to play" dialog in the room header.** One file serves players, contributors and Claude; it loads with the renderer only when opened. `v-html` is safe here because the Markdown is the repo's own, bundled at build time.
- **During a game the app bar and room header hide; a small ☰ button floated top-right (with the eye and watcher count floated just left of it, when anyone watches) opens a right-hand drawer with the room code, watcher count, How to play, Invite, TV, theme, Back to lobby and Leave. The lobby keeps its header, compact: room code, an eye with the watcher count, and icon buttons for How to play, Invite and Leave (TV lives only in the drawer).** On phones the two took about 180px a round needs, and nobody uses them mid-round. It opens from a button, not an edge swipe, because both phone OSes use edge swipes for Back. It's floated rather than fixed so each play view's top row (round, score) wraps beside it instead of being covered.
- **The watch page hides the app bar too, keeping its own header: room code and join link on the left, the game name centred, the eye and watcher count (this screen included), Full screen and Stop watching on the right.** A TV needs nothing from the app bar, and the room's header already has the only controls a watcher uses.
- **Game play views get `serverNow()`; `state` messages carry the server time.** Countdowns against server deadlines stay right on phones whose clocks are off.
- **Client lint uses `eslint-plugin-vue`'s `essential` preset (correctness only).** The `recommended` preset is mostly template line-wrapping rules, which is formatting, not bugs.
- **Host migration is core: ~2 min grace, then next player in join order (guests allowed), plus manual transfer.** Login gates creating rooms, not running one you're already in.
- **Display names: 1-16 chars, unique per room (case-insensitive), overridable per room, no profanity filter.** Simple and enough for a semi-public audience.
- **Rooms in memory; SIGTERM sends a restart notice.** Persisting rooms isn't worth the work at this scale; the reducer design keeps it possible later.
- **Game state must be plain JSON data (no Map, Set, Date, class instances, NaN); `createSim` checks it after every step, so every game test enforces it.** It's what keeps persisting rooms possible, and nothing else would notice a game quietly breaking that. Persisting would also need the seeded rng's position (one number). The game seed is logged at start, but there is no action log, so games can't be replayed yet.
- **Each room has a promise queue; every change (messages, timers, disconnects) runs on it, then broadcasts.** `prepareRound` is async, so without a queue two actions could interleave around it.
- **A fired timer re-checks its key when its turn on the queue comes, and is dropped if the key was cancelled or rescheduled meanwhile.** Work queued ahead of it can cancel it, so `cancel` and rescheduling a key mean what they say and games don't need stale-timer counters. Existing `round`/`turnSeq` guards in the games stay as a second line of defence.
- **A signed-in player who joins a room they're already in takes their seat back** (new token; the old tab gets a `removed` notice). That is how "the creator can reconnect from another device and still be host" works.
- **One connection per player; a second tab/device replaces the first.** Simpler than multiplexing, and it matches one-phone-per-person play.
- **The home page has two tabs, Join and Game Library; the tab lives in the URL (`?tab=library`).** A single game dropdown won't scale to many games, and players want to read rules before choosing. The library is public (browse, filter by name, style and player count, read rules); **Start a room** shows for any signed-in user, matching the server's `create_room` rule. The Join tab's create card stays for now.
- **Game styles (Card, Board, Dice, Deduction & bluffing, ...) are a fixed `GAME_STYLES` list in core, and each game's `meta` names one or more.** A fixed list keeps the library's Style filter short and the wording the same across games; several per game because e.g. Liar's Dice is both dice and bluffing. The filter only offers styles some game has.
- **The library's search field is always shown; the Style and Players filters sit in a menu behind a filter button with a dot while either is set.** Inline selects crowded the row and wrapped on phones; a menu floats over the list so opening it moves nothing, and a dialog would be heavier than two selects need.
- **Game menus list games alphabetically by name; the server sorts `/api/config` and the room's `availableGames`.** Registry order reflects when games were added, which means nothing to players; sorting at the source keeps the Join tab's dropdown, the lobby's game switcher and the library in the same order. Registry order still picks the server's fallback game.
- **Join errors show on the join form and clear on edit; toasts use `display-strategy="overflow"` (newest replaces current).** The default queue held each toast for its full timeout in turn, so a few wrong codes kept "no room" on screen long after the fix.
- **Manual multi-player testing uses a dev-only `dev-players.html`: an iframe per player, with client storage keys prefixed by the frame's `window.name`, and guest frames on a second host (`[::1]`) so they have no session cookie.** One window replaces juggling browsers; signed-in frames would otherwise merge into one seat. It isn't a Vite build input, and the admin app-bar button that opens it is imported only under `import.meta.env.DEV`, so neither ships.
- **In dev, the start-room form can open the new room in dev players and/or a watch window, each its own named pop-up window; the creating tab stays on the home page.** Saves copying the code into the grid and a second tab. The windows open blank inside the click (so they count as user-opened) and navigate once the room exists; staying home stops the tab pulling the seat back from P1. The options component is imported only under `import.meta.env.DEV`.
- **Rooms with nobody connected close after 10 minutes** (plus the 1h idle rule), so a creator isn't locked out of `MAX_ROOMS_PER_USER` by abandoned rooms.
- **Joining mid-game is allowed; the game decides what a late joiner sees.** Imposter shows a waiting view until the next round.
- **A late joiner plays from the next point where they can join cleanly: the next round when rounds stand alone (fresh word, question or deal; only scores carry over), otherwise the next game.** Round-based games can run many rounds, and sitting out the rest of the evening is worse than starting behind on points. Games whose rounds build on earlier play (hands, a board, dice lost) can't seat anyone until the game ends.
- **Over-size frames close the socket with 1009 instead of returning `error { validation }`.** `ws` enforces `maxPayload` by closing; there is no frame to answer. Invalid JSON and schema failures still get the error message.
- **Defaults: 30 websocket connections per IP, 10 messages/sec per socket, 20 join/reconnect attempts per minute per IP.** A family behind one NAT stays well under; code guessing doesn't.
- **Invite and the TV's Copy link open the share sheet only on devices with no mouse or trackpad (no `any-pointer: fine`); anything else copies to the clipboard, and the lobby's Invite confirms with a "copied" tooltip and a check on the button.** Chrome and Edge on Windows (touchscreen laptops included) have `navigator.share` too, and their share flyout is easy to miss, so the button looked dead; a toast at the bottom of a big screen is easy to miss too.
- **One spectator role for a shared TV and for remote watchers; display only, no host controls.** What they may see is the same either way, and two roles would mean two secrecy boundaries to get right; layout is the client's job. A TV that runs the room would raise who-may-press-what questions, so the host keeps those on their phone.
- **Spectators are kept apart from players (`room.spectators`) and see `view(state, SPECTATOR_ID)`, a reserved id no player has.** Games already show outsiders (late joiners) only public data, so no game needed changes, and spectators can never be dealt in, counted, made host or passed to lifecycle hooks.
- **The leak test checks `SPECTATOR_ID` in every state, and fails a secret that's visible to the spectator but hidden from some player.** A `visibleTo` written as "anyone except X" would otherwise quietly let the spectator in, and the harness skips viewers `visibleTo` allows.
- **Anyone with the code can watch (guests too, rate-limited like joins, at most 8 per room); players see a watcher count, and the host can't remove spectators.** The code already gates joining, which shows more; a spectator holds nothing secret, and the count keeps watching visible.
- **Spectators don't keep a room alive, and switching a tab from playing to watching detaches its seat instead of leaving.** A TV left on shouldn't hold a creator's room slot; the person whose browser it is keeps their seat to go back to.
- **Leaving the watch page never reconnects a saved seat; only opening that room's page does.** The same account may be playing that seat on a phone by then, and an automatic reconnect from the TV would pull it away ("You joined from another tab or device").
- **Games opt into the watch page with an optional `SpectatorView` (no `send` or `me`); without one it shows the player list.** A play view's "you'll be dealt in next game" outsider screen is wrong on a TV, and props without `send` make a display-only view by construction.
- **Spectator views lay out through core `SpectatorLayout`: the game left, scores and history right; from md up the page is one screen tall, the game scales down to fit its column and the side column scrolls on its own.** A TV can't be scrolled from the sofa, so the game must always be in view, and the side column is the part that grows (move logs). Scaling (a transform) keeps every game's layout as designed and can't feed back into its own measurement. Phones stack and scroll as before.
- **Move animations live in the shared board/table components, are client only, and play only for changes that arrive while the board is on screen; `prefers-reduced-motion` turns them off.** Players and the TV get the same motion from one place, games stay pure with no animation state on the server, and joining, reconnecting or opening the TV mid-game shouldn't replay moves.
- **Card games describe moving cards as `flights` worked out from the move log, and `CardTable` animates each new id once (Web Animations, on an overlay on the page); a deal is the one flight that plays on mount.** One animation engine for every card game, the move log already says what moved, and the table remounts with each game, so a deal seen on mount is a live one. The overlay sits on the page so cards can reach your hand below the table without a parent clipping them; a flight from your own seat starts at your hand. Faces fly only when the view already shows them (a call's turned-up cards, a played Last Card card).
- **A win is celebrated by core `WinCelebration`: a hand-drawn canvas confetti burst and a card that pops out of it and goes by itself, without blocking the page.** Every game with a winner can use the same moment, a few dozen lines of canvas don't justify a library, and the host can press New game straight away.
- **Move lists use core `MoveLog`: numbered from the game's first move and tinted by how the move went for the player who made it (each game's `moveTone`), not for the viewer.** Numbers tie the TV's big latest move ("Move 12") to the list under it, and one meaning of green and red reads the same on every phone and the TV. Neutral moves stay plain, so colour marks the moments that mattered.
- **On phones, move lists (and Liar's Dice's last round) open in a dialog from a button (core `MoveLogDialog`), like How to play, not an accordion.** An expanded accordion pushes the play view down and grows with every move; a dialog leaves the table where it is and scrolls on its own. The TV keeps its list inline, since nobody taps it.
- **Gone Fishin' and Cheat have a Move history setting (Off / Last 5 / All, default Last 5), applied in `view()` with kit `visibleMoves` and checked by the `hiddenMoves` secret; the latest move always shows.** Remembering who asked for what, or what's been claimed, is the skill in those two, so a full list is a crutch; trimming on the server means the setting holds for the TV and anyone reading the socket too. Last 5 helps younger players without giving the game away. A `logStart` count keeps move numbers right. Last Card, Liar's Dice and the board games don't get it: the table already shows what matters, or the list is only this round's public bids.
- **Last Card celebrates the game's win: in points scoring only when someone reaches the target, in rounds scoring every round won.** A points round win is one step toward the game, and confetti every few minutes would wear out the moment; in rounds scoring each round is the whole game.
- **Games that end with placings pass `standings` to `WinCelebration` for a podium (2nd, 1st, 3rd; gold, silver, bronze) with 4th and below listed under it; places come from kit `placings` (ties share a place, the next skips).** One rule for ties everywhere, and an empty step keeps 1st in the middle. Leavers aren't placed, as they can't win. With fewer than 3 placed it's the plain card: a podium of two says nothing the title doesn't.
- **Cheat's podium places by fewest cards left.** Only the first out wins, but cards left is how close everyone else came, and it's on the table for all to see.
- **Party-round TV views share core `WhoAnswered` (a chip per player that turns green when they answer, never what), not a whole shared header.** The prompts differ too much (a question, paint strips) and each game already has its prompt card; who's left to answer is the part that's the same, and the part a room watches.
- **On the TV, a live reveal drops its results in one by one (Flock's groups, Ballpark's board, Color Mix's guesses from the furthest so the closest lands last); opened mid-reveal, they're just there.** The reveal is the TV's moment, and it follows the rule that nothing replays on first render.
- **Score-limit and last-round wins use core `winTitle` and `scoreStandings`: the game's winners share 1st, everyone else is placed by score after them.** The game's own rule picks the winners (Flock's black sheep can't win even on top score), so the podium never contradicts the title.
- **Word Imposter's category goes to everyone, outsiders and the TV included, whenever the imposter gets it (any hint setting but none); with no hint, only the crew has it.** The TV is in the imposter's sight, so it can show only what the imposter already knows, and the `category` secret makes the leak test hold it to that. A late joiner gets the same.
- **Liar's Dice bids use the numbered `MoveLog`, plain while bidding; once called, the called bid is green if it held and red if it didn't, followed by the call, coloured by how it went for the caller.** A bid has no outcome until it's called, only the last one ever is, and colouring bids mid-round would hint at the dice.
- **The TV's turn marker keeps pulsing; on phones it doesn't.** A TV is watched from across the room, between glances, so the turn has to catch the eye; on a phone, the player's own "your move" cue does that job and a constant pulse would just be noise.

## Stack
- **TypeScript everywhere, pnpm workspaces.** Shared protocol and view types can't drift between server and client.
- **Vue 3 + Vite SPA with Vuetify 4, served by Express (one origin).** Vuetify covers almost every component needed; one origin means no CORS and simple cookies. Nuxt skipped since Express + `ws` already is the backend.
- **Text sizes use Vuetify 4's type classes (`text-display-*`, `text-headline-*`, `text-title-*`, `text-body-*`, `text-label-*`).** Vuetify 4 dropped Vuetify 3's `text-h1`-`h6`, `body-1/2`, `subtitle-*`, `caption` and `overline`, and an unknown class fails silently: until they were replaced, every one of them rendered as plain 16px text. Old to new: h3 → display-medium, h4 → headline-large, h5 → headline-small, h6 → title-large, body-1/subtitle-1 → body-large, body-2 → body-medium, caption → body-small, overline → label-large (not uppercased).
- **Vite pre-bundles every Vuetify component (`optimizeDeps.include: vuetify/components/*`).** Auto-import adds component imports after Vite's dep scan, so otherwise the first lazy page using a new component triggers a re-bundle and a full page reload mid-session.
- **Vitest for unit, core, auth and integration tests; no browser E2E in v1.** Covers the risky logic without the cost of Playwright.
- **Startup and shutdown live in `startServer()` (server.ts); index.ts only wires signals to it.** Tests run the exact shutdown path in-process. Sending a real SIGTERM to a child process isn't testable on Windows, where it kills the process before handlers run.
- **Relative imports use `.ts` extensions (`rewriteRelativeImportExtensions`, `erasableSyntaxOnly`); workspace packages export their TS source.** Works unchanged in Vite, Vitest, tsx and Node's native type stripping. The server build (milestone 4/5) must compile or bundle workspace packages for `dist/`.
- **Latest stable packages, installed with `@latest`, lockfile committed.** Greenfield project; no reason to start behind. Exceptions are recorded here.
- **Keep pnpm's default release-age policy, so "latest" can lag by about a day.** Holding back brand-new releases is a cheap supply-chain guard (on 2026-10-21 it resolved `vite` 8.3.4 and `@anthropic-ai/sdk` 0.135.0 because 8.3.5 and 0.137.0 were under 24h old).
- **Dependency build scripts allow-listed in `pnpm-workspace.yaml` (`allowBuilds`): `esbuild`.** pnpm blocks unreviewed build scripts; add a package here only after checking what its script does.
- **TypeScript pinned to 6.0.x, not 7.** `typescript-eslint` doesn't support TypeScript 7 yet (peer range < 6.1); revisit when it does.
- **`ws`, not Socket.IO.** The core already owns rooms, per-player broadcast (`view()` per recipient), token reconnect and a zod-checked protocol, so Socket.IO would duplicate them. `ws` keeps the browser on native `WebSocket` and lets tests drive plain clients. We add the two things Socket.IO would have given us: a 30s ping/pong heartbeat and a small `maxPayload`.
- **Auth checked in a `noServer` upgrade handler.** Origin, session and per-IP caps are checked before the websocket handshake completes.
- **MCP via `@modelcontextprotocol/server` (v2), not `@modelcontextprotocol/sdk` (v1).** v2 is the current SDK line.
- **SQLite via built-in `node:sqlite`, not `better-sqlite3`.** No native build, no build-script allow-list, no binding tied to a Node version. Costs: release candidate (not yet stable), no `.transaction()`/`.pragma()` helpers (we write a small wrapper). Better Auth supports it; if its CLI doesn't, use `better-sqlite3` for the CLI only.
- **The server runs its TypeScript directly on Node (type stripping); no server build step.** Node 26 strips types natively, workspace packages export TS source, and `erasableSyntaxOnly` keeps the code strippable. Only the client is built (Vite). `tsx` stays available but isn't needed.
- **Better Auth's schema is migrated at boot from code; the first admin comes from our `pnpm create-admin` script.** No CLI steps to forget on deploy, temp test databases just work, and the script uses the same config/env as the server.
- **Our Origin check runs in front of Better Auth too.** Better Auth skips its own check for requests without cookies, which would let another site sign people in (login CSRF).
- **The real client IP is computed once and handed to Better Auth in an internal header.** Better Auth's rate limits then use the same IP as ours, and a spoofed `X-Forwarded-For` can't dodge them.
- **Agent skills: only ones published by a package's own maintainers, copied into `.claude/skills/` and pinned in `skills-lock.json`.** So far that is Better Auth's (best practices, security, email/password); org and 2FA skipped since we don't use them. Vue's `vuejs-ai/skills` is community-run and Vuetify's only skill targets `@vuetify/v0`, so neither is in. Skills run with full agent permissions, so read the diff after `npx skills update`.
- **`.env` is read with Node's `process.loadEnvFile` from the repo root.** No dotenv dependency. Values starting with `#` (like the primary color) must be quoted.
- **Same Node major version (26) in dev and prod; `pnpm install` runs on the VPS.** `node:sqlite` ships with Node, so its API follows the Node version.

## Auth and access
- **Keep Better Auth with closed sign-up and the admin plugin.** Audience is semi-public now and the project may be self-hosted by others; it's mostly config.
- **Roles `user` and `admin` via the admin plugin's `role` column.** No custom user-management backend.
- **No email in v1; admins reset passwords.** Nothing to send email with yet; admin reset covers a small user base.
- **An admin password reset signs the user out everywhere (an `after` hook in `auth.ts`).** Better Auth's admin `set-user-password` keeps sessions, so resetting a compromised account wouldn't lock out whoever has it.
- **Game admin routes are mounted by core under `/api/admin/<gameId>` behind `requireAdmin` + Origin check.** Games get admin features without being able to forget auth.
- **Admins see open rooms at `/admin/rooms` (names, status, who opened it; no tokens or game state) and can join or close them.** Joining is the normal join flow and takes a seat like any player, so an admin can't watch secret views unseen; closing tells everyone "An admin closed this room." and frees the code and the creator's room slot.

## Data and AI
- **Two SQLite files: `auth.db` and one shared `games.db` with per-game prefixed tables and migrations.** MCP never touches accounts; one game DB avoids multiplying files, backups and WAL handling.
- **Categories live in one core `categories` table scoped by `game_id`, not in each game's rows.** Admins manage them directly (core Categories page per game), pickers and filters read the list instead of `SELECT DISTINCT`, and future games reuse it. Games reference categories by id with `ON DELETE RESTRICT`, may read/join the table filtered by their own `game_id`, and write through `services.categories`. This is the one exception to "games only touch their own prefixed tables".
- **Adding by category *name* (MCP, AI generation, and the admin Add dialog, a combobox) resolves the name to an existing category first and creates it only when nothing matches.** Matching (core `matchKey`, `CategoryService.resolve`) ignores case, accents, punctuation, "&" vs "and", a leading "the" and a plural "s", so "sport and games" lands in "Sports & Games"; creating or renaming into such a near-duplicate is refused. Different wording is not guessed: the MCP tool descriptions (`CATEGORY_REUSE_RULE`) ask Claude to check `list_categories` and reuse a category that means the same thing. The Add dialog used to pick from existing categories only; the user wanted to type new ones, and resolution keeps typos and plurals from cluttering the list.
- **Library words and questions de-dupe within their category by the same `matchKey` as category names, so "dog" is skipped next to "Dogs" and "t rex" next to "T-Rex"; adding skips them (the reason names the stored spelling), editing into one is refused.** The user wanted MCP and AI additions to stop creating spelling variants of existing entries. It's checked in code (core `findMatch` over the category's entries), not by a stored key column: migrations are SQL-only and can't compute the key, and libraries are small. The exact case-insensitive `UNIQUE` constraint stays as the backstop. Same entry in different categories is still allowed, and different wording is not caught.
- **With no category chosen, AI generation follows categories named in the admin's instructions ("5 each for Dinosaurs and Space"; core `categoryScope`), and generated names are resolved like typed ones before review.** The user wanted to set categories in the free text.
- **A category with words can't be deleted (the database refuses); words can be edited and moved instead.** No silent cascades that delete a library by accident.
- **Imposter migration `003_default_words` seeds a starter library (14 categories x 20 words, source `builtin`) with `INSERT OR IGNORE`.** A fresh install has categories to pick from; an existing library keeps its own words and gains only what's missing. The list in `default-words.ts` is frozen with the migration; more defaults mean a new migration. Tests start from an empty library unless they ask for the seed.
- **No ORM: plain SQL migrations and prepared statements behind typed service functions (`library.ts`, `ai.ts`).** A handful of tables and queries, per-game migrations owned by each game, and live game state in memory leave an ORM little to do. If later games need relational data, add Kysely (already installed via Better Auth) as a query builder.
- **Migrations stay per game; a game id change goes through `renamedFrom` on the game module.** One database suggested one central migration list, but per-game migrations keep a game one folder plus a registry line, and keep the table-prefix check enforced. `renamedFrom` makes a rename safe without editing applied migrations: before the game's migrations run, the core moves the old id's recorded migrations, categories and AI usage to the new id and accepts the old table prefix in old migrations; the game's own new migration renames its tables.
- **Once every database has applied a rename, the game's migrations may be squashed onto the new id (the one exception to append-only), keeping their migration ids, and `renamedFrom` dropped from the game.** Fresh databases then create the new tables directly instead of carrying old names forever; existing ones already have those ids recorded and skip them. Done for Flock after the dev and production databases had applied `003_rename_from_herd`: 001 and 002 now create and seed `flock_questions`, 003 is gone (its record stays in those databases, unused). The `renamedFrom` feature stays in the core for future renames.
- **Shared AI service caps daily output tokens (plus per-admin rate limit) and logs to `ai_usage`.** Tokens are game-neutral and close to real spend; per-call limits in game units stay in each game.
- **Only admin routers (and MCP tools) receive `services.ai`; gameplay hooks and public routes get `null`.** The API key is billed, so a guest or player must never be able to reach a paid call, even through a future game's `prepareRound` or public route.
- **AI is optional.** Self-hosters without an API key still get a working platform.
- **AI calls use one strict tool with `tool_choice: auto`, not a forced tool, and validate the result.** Forced tool choice is rejected by several current models and the model is configurable. A missing or malformed call becomes `AiError('invalid')`, and generation retries once.
- **`AiError` (codes `cap`, `rate_limited`, `invalid`, `refused`, `api`) lives in packages/core.** Games map AI failures to HTTP statuses without importing server code.
- **AI generation (admin Generate dialogs and the `*_generate_*` MCP tools) takes optional free-text instructions from the admin, up to 500 characters, worded by core `instructionsLine` and placed under the game's system rules.** The user wanted to say things like "really easy, for young kids" without a setting for every wish; the admin is trusted, and validation still screens the output. Imposter's `hintStyle` stays as its own field because it overrides a specific default.
- **Usage is logged even when the response is unusable, and the per-admin limit is counted from `ai_usage`.** Tokens were spent either way, and the limits survive restarts.
- **Game admin routers read the signed-in admin from `res.locals.user` (`AdminUser` in the contract).** The core already resolved it in requireAdmin; games don't re-check sessions.
- **The MCP process reads the repo `.env` (without overriding its own env), so `imposter_generate_words` appears when the server has a key.** One place to configure the key, model and caps.
- **Generated words are reviewed by an admin before saving (UI path).** Keeps junk and spoiler hints out of the library.
- **The generate dialog has an opt-in "no spoilers" mode (`save: true`): the server saves directly and returns counts per category only, never words, hints or skipped entries.** An admin who also plays shouldn't see the words; validation and de-duping still screen out junk, and returning counts only (rather than hiding the words in the client) keeps them out of devtools too.
- **Imposter MCP add/generate tools tell Claude not to list the words or hints in its reply (counts and categories only) unless explicitly asked, in the tool description and as a `note` on the result.** The person adding words may be about to play. The words still appear in the tool-call input, which Claude Code shows collapsed.
- **Imposter hints default to a single, loosely related word (seeds, built-ins, MCP guidance, AI prompt); migration `004_vague_default_hints` rewrites the starter hints that are still unedited.** Phrase hints ("Squirt your friends") handed the imposter the word. Longer hints are still allowed when asked for (`hintStyle` on generation); validation does not enforce one word.
- **The admin area has an Assistant chat (`/admin/chat`, `POST /api/admin/chat`) where Claude manages the libraries with the same `<gameId>_<tool>` tools as the MCP server (core `gameMcpTools`), minus the `generate_*` tools since Claude writes entries itself.** The user wanted to type what they want instead of using each page. It sits behind the Origin check and `requireAdmin` like every admin route, so it only works from the signed-in admin's own browser session; the server runs the conversation (in memory, per admin, deleted by New chat (`DELETE /api/admin/chat/:id`, owner only) or after 2 idle hours or a restart) and the client only sends text, so a request can't inject tool calls or results. It has its own model (`ANTHROPIC_CHAT_MODEL`, default Claude Opus 5.5, because it plans multi-step tool use), its own per-admin hourly message limit (`AI_CHAT_MESSAGES_PER_HOUR`), up to 12 model calls per message, and counts toward the shared daily output-token cap (logged as `chat` in `ai_usage`, excluded from the generation hourly limit). Removing or deleting is confirmed in conversation (system prompt), not by a separate approval step. Progress streams as NDJSON so long turns don't hit proxy timeouts.
- **Below Vuetify's `md` breakpoint the admin nav is a temporary `v-navigation-drawer`, opened by a button naming the current page; desktop keeps the sidebar card.** On a phone the stacked nav came before the page content. Both render one `navItems` list.
- **One stdio MCP server with namespaced tools from every game.** One registration covers all games; driving it from Claude Code needs no API key.
- **The MCP process runs migrations on games.db at start and defaults GAMES_DB_PATH to <repo>/data/games.db.** It works before the web server has ever run, from any working directory.
- **Games may expose a read-only `publicRouter` at /api/games/<id> (GET only, rate-limited).** The lobby's category picker needs library categories, and admin routes are the wrong place for player-facing data.
- **Library entries carry a `batch` number, one per add call (MCP, admin save, generation), and the library games' "Recently added" source plays the newest batch first (core `@wsfg/core/library`).** The user wanted to play what Claude just added without a throwaway category. A batch is per call, not a time window (generated Tuesday, played Saturday still works); MCP add/generate tools take an optional `batch` so a request that spans several calls (one per category) stays one batch, and an unknown number starts a new one rather than erroring. Order is least used first, then newest batch (random within it), then older batches, then pre-batch rows by newest id, so a played batch gives way to fresh older entries instead of repeating; the host gets a notice when the pick isn't from the newest batch. Existing rows stay NULL rather than being backfilled.
- **Library admin pages have a "Clear used" action that deletes every entry played at least once (`times_used > 0`), in the filtered category or in all of them, after a confirm showing the count (core `removeUsed`).** The user wanted to drop what they've already played rather than replay it once the fresh entries run out. It deletes rather than resetting `times_used`, ignores the search box (category only, so the count comes from the category stats), and starter words go too; a library emptied this way falls back to the built-in list as usual. Admin page only, not an MCP tool.
- **prepareRound signals a library fallback as `{ builtin: true, notice }`; the pure reducer picks the built-in word with ctx.rng.** Repeat-avoidance for built-in words stays in game state, and the notice still comes from the game.
- **Full v1 scope: game, auth, library, admin panel, AI generation, MCP.** Explicit choice to build it all in v1.

## Word Imposter rules
- **Imposter chosen uniformly at random every round (repeats allowed).** A shuffle bag would let players deduce who hasn't been imposter yet.
- **Round player order setting, default `rotate`: random first round, then last round's order moved on one seat; `random` reshuffles every round.** Rotating gives everyone a turn going first (and avoids the same person always opening); the order is fixed within a round's rotations either way. Leavers drop out of the line and newcomers join its end, so a mid-game join never reshuffles everyone. In `rotate`, the host can tick "Randomize player order" on Play again for a one-off reshuffle (a flag on `next_round`, not a setting, since settings only change in the lobby); rotation carries on from the new order.
- **Hold-to-reveal for the role card and the judge's word.** People play around one table; the word must never sit on screen for the imposter to glance at.
- **Spoken guess confirmed by a judge's tap (host, or first crew member if the host is imposter).** No spelling issues; trust-based by design.
- **In typed mode the imposter types the guess, but the judge still rules on it.** Typing settles "what did they actually say"; the judge keeps misspellings and near-misses from being auto-failed. One try, locked once sent, so the imposter can't read the room and retry. Everyone sees the guess. A sent guess stands if the imposter then disconnects.
- **Configurable catch/escape points (defaults 1/2), guess bonus default +1.** Defaults suit 4-7 players; the table can rebalance for bigger groups.
- **Ballots are secret during voting, then public (who voted for whom) on the reveal, guess-check and results screens.** No bandwagoning while voting; afterwards the table wants to talk it over, and the 5s reveal alone is too short to read it.
- **A wordless pulsing screen-edge glow means the game is waiting on you** (your clue turn, your vote, the imposter's guess and the judge, the host's next round). Host-only overrides don't trigger it. Phones lie on the table, so the cue must be visible at a glance without reading. The shell draws it (`AttentionGlow` in `RoomPage`); a game only supplies a pure `needsAction(view, me, room, settings)` in its client module, so every game gets the same cue.
- **Ties mean the imposter escapes.** Crew must clearly agree to catch them.
- **Typed clues reject the secret word and exact repeats (case-insensitive).** Prevents giving the word away and lazy copying.
- **Typed clues are listed by player (name as a small heading, clues as a bulleted list) and stay visible while voting.** Voters compare each player's clues side by side; the view already carries them.
- **Clue timer auto-skips in typed mode but is visual only in spoken mode.** A hard cut-off while someone is talking is annoying.
- **A disconnected imposter stays in the round; their guess counts as missed after a 15s grace.** The game never stalls and their role still matters.
- **The imposter's clue is never checked against the secret word.** Rejecting it would let the imposter retry guesses until one bounces, revealing the word. Crew clues equal to the word are still rejected.
- **REVEAL auto-advances after 5s; the host can force the end of voting (`end_voting`).** Neither had an action in the original table; a timed reveal keeps the table's attention without an extra tap.
- **Late joiners see a `waiting` role (no word) and play from the next round.** Joining mid-round must not hand anyone the secret word.
- **If the imposter leaves before the reveal, the round is voided (no points).** Nothing meaningful is left to score; the host starts the next round.
- **The built-in word list shipped with the reducer (milestone 3), not the library (milestone 6).** It needs no DB, so the game is playable before the library exists; it stays as the last-resort fallback.
- **Word source is "All words" or "Added only" (skips library rows with source `builtin`, i.e. the seeded starter words); there is no "built-in list only" option.** Nobody picks the starter list on purpose, while hosts who have played it through want fresh words. "Added only" falls back to starter words (with a host notice) when added ones run out, then to the in-code list. A third option, "Recent", plays the newest batch first (see Data and AI); the toggle labels are shortened to All / Added / Recent to fit a phone.

## Liar's Dice rules
- **Liar's Dice is the second game.** It's built on hidden per-player information like Imposter but has no words or votes on players, so it tests whether `kit` and `ui` really fit a different game.
- **Perudo rules: wild ones on by default (opening bid can't be on ones, half/double+1 when switching), spot on optional.** They're the best-known rules; wild ones and the halving rule keep late rounds with few dice interesting.
- **Only the next player can call, and never on their own bid.** It's the classic turn structure, and it keeps the game turn-based rather than a race to tap.
- **The player who lost (or gained) a die starts the next round.** Standard rule; it gives the loser the opening bid.
- **A disconnected player's turn passes after the 15s grace with the bid unchanged; nobody auto-bids or auto-calls for them.** Any automatic move would be an arbitrary choice that can cost a die.
- **A player leaving mid-round restarts the round (re-roll, no die lost).** The bid was made against dice that are now gone, and nobody should lose a die over it.
- **One point per match won, carried across matches; seats move on one each match.** A match is the natural unit to win; rotating seats changes who opens.
- **Your dice show only while held (`HoldToReveal`).** Same reason as Imposter's role card: phones lie on a shared table.
- **REVEAL stays up for 8s, then the next round rolls; a summary of the last challenge stays visible while bidding.** Counting dice takes longer than reading an Imposter vote, and the summary keeps "what just happened" readable after the timer.
- **No bid timer in v1.** The disconnect grace stops a stalled turn; a timer can come later if tables want one.

## Flock rules
- **Flock is the third game (id `flock`, formerly `herd`).** It's the simplest library-driven game after Imposter and the first to compare free-text answers, so it tests the categories table and library pattern with a second game.
- **Renamed from Herd Mentality to Flock, and its pink cow to the black sheep, before open-sourcing.** Herd Mentality is a commercial game by Big Potato Games and the name is very likely trademarked, and the pink cow is its signature piece. Mechanics are free to use; names and branding aren't. The id moved from `herd` to `flock` too, so code, tables, routes and MCP tools match the name; `renamedFrom` and migration `003_rename_from_herd` carried existing libraries over, then the migrations were squashed (see Data and AI).
- **Score limit defaults to unlimited (options 5-20).** Family tables often play "a few questions" and stop; a limit is there for a proper race.
- **The flock is a strictly biggest group of at least 2; a tie for biggest scores nobody.** That's the original party game's rule, and it makes a split table a real loss rather than a shared win.
- **Black sheep on by default: exactly one lone answer becomes the black sheep, who can't win.** The odd-one-out twist keeps lone answers interesting; with no score limit it's just a badge of shame.
- **The win check uses who is the black sheep after the round is scored.** Points and the black sheep move together, so reaching the limit in the same round it passes to someone else wins; a stricter "start the round without it" rule was considered and not taken.
- **Players who reach the limit in the same round win together.** The whole flock scores at once, so simultaneous wins are common; a tie-break round would be arbitrary.
- **Answers are matched after normalising (case, accents, punctuation, spaces, leading "the"/"a"/"an", a plural "s" on words of 4+ letters not ending in ss/us/is); the host merges the rest.** Automatic fuzzy matching would merge answers the table thinks are different ("Mars" bars vs Mars); the host's eye is the source of truth, like Imposter's judge.
- **The host checks matches by default (setting), and is a player too.** Near-misses are common with typed answers; a family table trusts the host, and the groups are on everyone's screen while they do it.
- **Answers can be changed until the reveal, and who has answered is public.** Like Imposter's votes: changing your mind is harmless, and the table wants to see who it's waiting for.
- **A disconnected player who hasn't answered doesn't hold up the reveal and sits the round out.** The game never stalls on a dropped phone.
- **One frozen starter list serves as the seed migration (`002_default_questions`) and the in-code fallback.** Imposter needed two lists because its seed outgrew the fallback; here one list keeps a fresh install and an empty library playing the same questions.
- **Your sent answer sits behind `HoldToReveal`.** Phones lie on the table, and a neighbour copying your answer would join your flock.
- **Core `ScoreBoard` has a `badge` slot for a per-player marker (Flock's black sheep).** Copying the scoreboard into a game to add one icon would fork it.
- **Questions aren't secret, so the MCP tools may show them.** Knowing the question in advance doesn't help much: the game is about guessing what others will say.

## Color Mix rules
- **Color Mix is the fourth game (id `colormix`), with no library.** Random colours need no content, so it's a pure game like Liar's Dice.
- **Colours mix like paint (Kubelka-Munk), not like light.** Players expect blue + yellow to make green; an RGB average makes grey, which feels wrong. The user chose paint.
- **The mixing maths is vendored from spectral.js (MIT, v3.0.0) into `server/spectral.ts`, not added as a dependency.** The package is untyped UMD; a typed copy of the few functions used keeps the answer pure and pinned (a library update can't silently change answers).
- **Closeness is OKLab distance, shown as a percentage to 2 decimals: `100 × e^(−distance / 0.25)`.** OKLab is perceptual and simple; a percentage reads better at the table than a raw distance. Whole percentages showed two different guesses as equal (85% and 85%) with one ranked above the other. A straight scale was tried twice: 0% at 0.5 gave a plain grey guess 75% (most colour pairs are under 0.2 apart), and 0% at 0.25 felt harsh and showed two different far-off guesses as 0.00% with a winner between them. The curve gives grey about 61%, never reaches 0, and keeps far-off guesses apart.
- **Scoring is a setting: ranked by default (1 point per player you beat), or closest only.** The user offered both. Ranked keeps every guess worth something; "players you beat" handles ties and missing guesses without special cases.
- **The game length is a number of rounds, unlimited by default, and the highest total wins.** Ranked points grow with the table's size, so a score limit would feel different by group size. The user chose rounds.
- **Difficulty sets the colours to mix: easy 2, medium 3, hard 4, or all difficulties (random each round).** Replaced a free 2-6 count: the user found 6 too many, and named levels read better than numbers.
- **Random colours are vivid (saturation 50-100%, lightness 25-70%), sometimes one white, at least 0.12 OKLab apart.** Fully random RGB gives many muddy, near-identical colours.
- **The colours to mix show as one strip of flush vertical swatches, like a paint chip.** The user found small, spaced-out circles harder to compare.
- **Guesses can be changed until the reveal and sit behind `HoldToReveal`; who has guessed is public.** Same reasons as Herd's answers.

## Tic-Tac-Toe rules
- **Tic-Tac-Toe is the fifth game (id `tictactoe`), exactly 2 players, no settings.** The user asked for a simple 2-player game; the classic rules need no options.
- **`secrets` is empty and there is no leak test.** Both players see the whole board; `runLeakTest` refuses a game with no secrets, and adding a fake one would test nothing.
- **Marks are random for the first game, then swap every game (`nextTurnOrder` 'rotate'); X always moves first.** Moving first is an advantage, so it alternates.
- **A disconnected player's turn is never skipped.** With one move per turn and two players, skipping hands the other player two marks in a row, which breaks the game; the other player can wait or leave.
- **A player leaving mid-game ends it with no points (`abandoned`).** A win by forfeit would reward the one left for a game that wasn't played out; the room holds 2, so a newcomer joins for the next game.
- **Wins score 1 point, draws score nothing; scores carry across games.** Between two players the win count is the score that matters.

## Drop Line rules
- **Drop Line is the sixth game (id `dropline`), a drop-discs-and-make-a-line game for exactly 2 players.** The user asked for one; the name avoids the trademarked brand of the best-known version and has no number in it because the line length is a setting.
- **Line length 3-6 (default 4) and a small / standard / large board per length, from a fixed table.** Free column and row counts would allow boards that play badly (too cramped to block, or nearly always drawn); 6 is the longest line that fits a board of about 11 columns, the most a phone can show with tappable columns.
- **Red and blue discs, red first.** Two colours that stay distinct in light and dark themes, and not the best-known version's red and yellow.
- **Lines longer than the setting count as wins, and the whole line lights up.** Dropping a disc can join two shorter lines into one longer than required; refusing that win would be a strange rule.
- **Disconnects, leavers, colour swapping and scoring work as in Tic-Tac-Toe.** Same two-player structure, same reasons.

## Ballpark rules
- **Ballpark is the seventh game (id `ballpark`): Wits & Wagers mechanics under a new name.** Wits & Wagers is trademarked; mechanics are free to use. "Ballpark figure" describes the guessing half in one word.
- **Win rule, scoring and bet visibility are all settings (defaults: without going over, odds, hidden).** The user wanted each variant available. The defaults are the original game's rules, except hidden bets, which stop players copying the table's best guesser.
- **Odds by distance from the middle slot (2 up to 5; two central slots pay 3 with an even count; All too high pays 6); writing the winning guess scores 3.** That's the original betting mat, computed from the slot count rather than fixed spaces.
- **Bets are 2 tokens each; chips scoring lets a token carry a stake from your score, and a token without a stake still wins its odds.** Tokens alone keep every player in the game even with no chips, as the original's betting markers do; scores never go negative.
- **Questions are stored with one metric unit (or a unit-free one) and converted for an `imperial` room setting, default metric.** The user asked for it; one stored unit keeps the library single-sourced. The question text never names a unit, so it reads the same in both systems.
- **A converted answer is rounded before play (whole numbers from 100 up, else 3 significant figures, or one decimal for temperatures so 37 °C reads 98.6 °F), and scoring uses the rounded value.** "Without going over" must be judged on the number players see, not a hidden 1082.68.
- **Answers are secret during play, so MCP add/generate tools reply with counts only.** As with Imposter's words: the admin adding questions may be about to play.
- **A leaving player's guess stays on the board once betting has started.** Others may already have bet on it.
- **Core `ScoreBoard` shows negative round points as a red "−N".** Chips scoring can lose points; showing "+-3" in green would be wrong for every future game that can lose points too.
- **Guesses are typed into a decimal keypad field with a ± button.** Phone number pads often have no minus key, and some answers (record low temperatures) are negative. Commas and spaces typed as digit grouping are ignored.

## Gone Fishin' rules
- **Gone Fishin' is the eighth game (id `gonefishin`): the classic ask-for-a-rank card game under its own name.** The user asked for it and chose the name to avoid any trademark question over the traditional one; a distinct name also matches Flock, Drop Line and Ballpark.
- **Deck helpers (`standardDeck`, `deal`, `Card`) go in `kit`, and `PlayingCard` and `CardTable` in `ui`.** Every card game in `games/IDEAS.md` needs them, and Liar's Dice could move onto the table too.
- **Seats sit around an oval table, rotated so you're at the bottom.** The user asked for a poker-style table; turn order then matches where people appear, and you see everyone's card count at a glance.
- **Each player picks Table or List for `CardTable`, saved in their browser; with no choice yet, screens up to 520px wide get List.** The user wanted it per player, not per game: six seats round an oval are tight on a phone. The list starts with you and runs in turn order, like the table clockwise from the bottom. The never-throw `localStorage` helpers moved from the client to `@wsfg/core/ui/storage` so core components can keep preferences, with the dev-players frame prefix intact.
- **2-6 players, 7 cards each with 2-3 players and 5 with 4-6.** The usual rules; with more than 6, one deck leaves too small a pond.
- **Books are laid down automatically.** Spotting four of a kind takes no skill, and a forgotten book would only stall the game.
- **Lucky catch (draw the asked rank, ask again) is a setting, on by default.** It's the most common house rule and some tables play without it.
- **An empty hand draws one card from the pond and carries on; with the pond empty too, you're done.** That keeps players in the game as long as cards remain, and the turn never names someone who can't ask.
- **Most books wins 1 point; ties each score 1. Scores carry across games.** Same match-point scoring as Liar's Dice; a book count would favour bigger tables.
- **Seats stay put between games and the first turn moves on one seat.** Players keep their place at the table, and a different player starts each game.
- **Every ask and its result are public, in a log of the game's moves.** At a real table they're said out loud, and remembering who asked for what is the skill of the game.
- **A disconnected player's turn passes after the 15s grace; nobody asks for them.** As in Liar's Dice: an automatic ask would be an arbitrary choice.
- **A leaver's hand is shuffled into the pond and their books stay down; fewer than 2 players left ends the game with no points.** All 13 books stay reachable without inventing a new end rule.
- **Your hand isn't behind `HoldToReveal`.** You read it every turn, and cards are held in the hand rather than left on the table.

## Last Card rules
- **Last Card is the ninth game (id `lastcard`): the classic colour-matching shed-your-hand game under its traditional generic name.** UNO is a Mattel trademark; the user chose the name. Mechanics are free to use.
- **Its 108-card deck, card type and card face live in the game, not in `kit`/`ui`.** They're specific to this game; it reuses `deal`, `CardTable` and `PlayingCard`'s face-down back.
- **Scoring is a setting: card points to a target (default, 500) or 1 point per round won.** The user wanted both. Points scoring counts games won as the carried score and keeps the running points per game.
- **Stacking, draw until playable, 7-0 swaps and jump-in are settings, all off by default.** The user picked these house rules; off by default plays the official rules.
- **The last-card call is a setting: Call (press it or be caught for 2, default) or Automatic.** The user wanted both. A late call is allowed until someone catches you, and the catch window closes when the next card is played or drawn, so it stays a race between the forgetful player and the table.
- **The Last card! button is shown and pressable at any hand size.** Enabling it only at two cards would remind the player to call, which is the skill being tested. For the same reason the attention glow ignores an exposed player.
- **Wild Draw Four is only playable with no card of the current colour, enforced, with no challenge.** A challenge needs the challenged hand shown to one player and a second decision round; enforcing gives the same legal play without either. When answering a stack it may be played regardless, since you're passing on a penalty, not choosing to start one.
- **Stacking: Draw Two on Draw Two, Wild Draw Four on either, never Draw Two on Wild Draw Four.** The most common house version.
- **After drawing, the drawer always chooses Play it or Keep it, even when the card can't be played; with stacking, a player facing a draw card always gets to choose too.** Passing automatically would tell the table the drawn card was unplayable, or that the player holds no draw card: hidden-hand information. One extra tap is the price.
- **A wild turned up as the first card goes back into the pile; other first cards act as if the dealer played them, except Reverse, where the dealer goes first anticlockwise.** The official rule has the first player name a wild's colour, an extra step before the first turn; Reverse follows the official rule.
- **A disconnected player's turn is taken after the 15s grace: they take a pending stack, keep a drawn card, or else draw one; nobody plays a card for them.** Skipping without a draw would reward disconnecting, and choosing a card to play would be an arbitrary move.
- **A leaver's hand is shuffled into the draw pile and a stack waiting on them is dropped; fewer than 2 players left ends the round with no points.** As in Gone Fishin'; nobody else should take a penalty aimed at someone who left.
- **Hands are revealed on the results screen.** In points scoring they are what the winner scores, so the table can check the count, as when hands are turned up at a real table.
- **With the draw pile and the reshufflable discard both empty, a draw takes what there is (perhaps nothing), penalties included, and play moves on.** It only happens when the hands hold nearly the whole deck; stalling the round or adding a second deck would be worse, and every play puts a card back to reshuffle later.
- **Jump-in reuses `play` from a player whose turn it isn't; the room's action queue settles races and a late jump-in is refused because the top card changed.** No timers or claim windows: first to send wins, as at a table.

## In Order rules
- **In Order is the tenth game (id `inorder`): Ito's mechanics under a generic name, and the first co-op game.** It was in `games/IDEAS.md` under that name; Ito is a commercial game, and mechanics are free to use.
- **Clues and ordering are one phase: clues appear in the shared line as they arrive, and anyone can drag any card at any time.** Ito is played by talking it over while cards are placed; a separate clue phase would make the table wait on its slowest writer before anyone can start arranging.
- **The reveal waits for everyone connected to tap Ready, and any move or clue edit clears every Ready; the host can reveal anyway.** In a co-op game the table should agree, and clearing on change stops a late drag from going through on stale agreement. A disconnected player doesn't block it, as elsewhere.
- **Mistakes are the fewest cards that would have to move to fix the line (cards − longest increasing run), 1 life each.** Counting out-of-order pairs, or Ito's "every lower card still in hand", punishes one card placed far from home as heavily as a scrambled line.
- **Settings: rounds (default 5, or until out of lives), lives (default 3, 1-5), numbers each (default 1, 1-3).** Small tables need more cards to be a challenge; an endless mode gives a "how far can we get" score. No timer: the game is the conversation.
- **A clue containing your own number as a number is refused; other digits are allowed.** "Never say your number" is the one hard rule, but banning every digit would refuse fair clues like "101 Dalmatians".
- **Numbers are behind `HoldToReveal`, and clue fields are labelled by rank ("Your lower number"), never by number.** Phones lie on the table; a neighbour who sees your number has the round solved.
- **Card ids are `<playerId>#<k>` in deal order (not sorted) and the line starts in seat order.** Anything derived from the numbers before the reveal would leak their order.
- **The drag-to-order list is `OrderList` in `@wsfg/core/ui`, written on pointer events with no new dependency.** HTML5 drag and drop doesn't fire on touch screens, and ranking games in `games/IDEAS.md` could use the same list.
- **Themes aren't secret, so the MCP tools may show them.** Knowing the theme gives nothing away; the numbers are dealt at play time.

## Cheat rules
- **Cheat is the eleventh game (id `cheat`): the classic bluffing card game under its traditional UK name.** It was in `games/IDEAS.md` as "Cheat / BS"; "BS" doesn't suit a family platform, and "I Doubt It" is less known.
- **2-10 players with one deck, all of it dealt.** Two can play (you still can't tell which of your opponent's cards went on the pile), and ten still get five cards each.
- **Claims are a setting: Next rank (A, 2 … K, wrapping; default) or Nearby (same, one up or one down).** Next rank is the usual rule; Nearby is the common house rule that makes forced lies rarer.
- **A play is 1-4 cards, and the count is always true.** At a real table everyone sees how many cards go down; four is the most of one rank a deck holds.
- **After each play there is a call time (3/5/10s, default 5s) before the next play; calls stay open until the next play.** Otherwise a quick next player could shut the table out of calling. The window is a timer in state (`stage: 'calling'`), not a comparison with `ctx.now`, so `createSim` and the leak test can move through it.
- **A call names the play it's for (`{ play }`), and a call on a play that's already been called or covered is refused.** Two players tapping at once, or a tap landing just after the next play, must not hit a play nobody meant to call.
- **After a call, play goes on with whoever's turn it already was, and the claims carry on.** The simplest common rule; restarting the sequence would give the loser of the call a free choice.
- **Going out wins only once the call time passes uncalled.** The last play is the one most worth calling; a lie caught there means picking up the pile and playing on.
- **The pile's cards are hidden from everyone, including the players who put them there; only a call turns up, and only the called play.** Your memory of what you played is yours to keep, as at a table, and a secret the view doesn't need.
- **A disconnected player's turn passes after the 15s grace without a play, and the claim to make stays the same.** Playing for them would be an arbitrary choice of cards and claim.
- **A leaver's hand is set aside, out of the game; if theirs was the latest play it can't be called.** Adding it to the pile would hand someone else their cards, and a call on a player who's gone has nobody to pick up the pile. Fewer than 2 players left ends the game with no points, as in Gone Fishin'.
- **The winner scores 1 point; scores carry across games.** Same match scoring as Gone Fishin' and Liar's Dice.
- **The attention glow shows on your turn, never for a callable play.** A cue to call would hint that the play is worth calling.
- **Your hand isn't behind `HoldToReveal`.** As in Gone Fishin': you read it every turn.
- **`rankName` ("sevens", "one ace") moved from Gone Fishin' to `kit`.** Cheat needs it too, and it names a kit `Rank`.

## Dots and Boxes rules
- **Dots and Boxes is the twelfth game (id `dotsandboxes`) under its traditional name.** The name is generic and owned by nobody (the game dates from 1889), like Tic-Tac-Toe and Cheat, so it passes the naming rule in `games/CLAUDE.md`; the user chose it over a custom name.
- **2-4 players, not 2 as in `games/IDEAS.md`.** The game plays well with more, and more than 4 colours stop being easy to tell apart on a small board.
- **Square grids of 3-7 boxes per side (default 5).** 8 dots across is the most a phone fits with comfortable tap targets; 5×5 is the usual size and its 25 boxes can't tie between two players.
- **Seat colours red, blue, green, orange follow the turn order; seats rotate each game (`nextTurnOrder` 'rotate').** Moving first changes the game, so it moves round; colours by seat mean red always goes first, as in Drop Line.
- **Closing a box means drawing again, and that is compulsory.** It's the standard rule; the endgame strategy (giving away boxes to keep control) depends on it.
- **Players tied for the most boxes each score 1 point.** With 3-4 players a tie for first is common, and calling it a draw would waste a whole game; between two players a shared point changes nobody's lead.
- **A disconnected player's turn is skipped after the 15s grace only while 3 or more are in the game; with 2 it waits.** With 3-4 players, one locked phone shouldn't stall the rest; with 2, a skip hands the other player two turns in a row, as in Drop Line.
- **A leaver's seat and boxes stay on the board, they're skipped and can't win; under 2 players left ends the game with no points.** Removing their boxes would reopen closed squares; same leaver shape as Cheat.
- **Line tap targets are diamonds (the line's two dots and the centres of the boxes either side).** They tile the board without gaps or overlaps, so every point picks exactly one line and targets stay as large as the grid allows.
- **Boxes show the owner's initial as well as their colour.** Colour alone fails colour-blind players.

## Old Maid rules
- **Old Maid is the thirteenth game (id `oldmaid`) under its traditional name.** The name is generic and owned by nobody, like Cheat and Dots and Boxes; the user chose it over a custom name.
- **One deck with the queen of clubs taken out, all dealt, 2-10 players.** The usual way to make an odd queen without a joker (kit's `Card` has none); dealing everything matches Cheat, and ten players still get five cards each.
- **You draw from the previous player still holding cards, then the turn passes clockwise.** The traditional rule (you offer your hand to the player on your left); skipping players who are out keeps the chain unbroken.
- **Pairs are any two of a rank; Match colour (off) is a setting.** Any rank is the common family rule; same-colour pairs are the stricter traditional variant.
- **Pairs go down automatically, the deal's included.** As with Gone Fishin' books: there's no choice in it, only taps.
- **Format is a setting: Classic (default; every player but the Old Maid scores 1) or Royale (the Old Maid is eliminated each round; the last player in wins 1 point).** The user chose Classic scoring and asked for Royale. Points to everyone but the loser fits a game about not getting caught; Royale gives an evening a knockout.
- **In Royale, a late joiner waits for the next Royale; in Classic, for the next round.** Royale rounds build on each other (who's eliminated); Classic rounds stand alone (the late-joiner rule in Core).
- **A leaver's hand is dealt out round the players still holding cards and new pairs go down; under 2 players left in the round, or in the Royale, ends it with no points.** The user approved it. Shuffling it into a pile, as in Gone Fishin', would take the odd queen out of the game; the leaver shape is otherwise Cheat's.
- **A disconnected player's turn is taken after the 15s grace with a random draw.** Drawing is blind, so it's the very move they'd make; skipping would leave their hand stuck in the chain.
- **The order of a hand is a secret: with Arrange hand off the server shuffles a hand before each draw from it and shows its owner the hand sorted; with it on, the owner's order stands and cards received land in a random place.** A sorted hand would tell the drawer which place holds the queen; a card received at the end would tell the next drawer where the latest card sits.
- **Arrange hand (off) lets players rearrange or shuffle their hand to bluff.** It's the table trick of offering the queen sticking up, but it adds actions and a drag, so it's opt-in.
- **A card taken that makes no pair is visible only to the drawer and the giver.** Both know it at a real table; everyone else sees a card change hands.
- **No `WinCelebration`: the round ends with core `LoseReveal` (greyed screen, the old maid card flipping up, a rain cloud over the caught player), Royale's final round included.** The user asked for the opposite of confetti: the moment is who got caught. It's core, as `WinCelebration`'s counterpart, so a later game about a loser has it ready.
- **The face-down fan you pick from (`PickFan`) is game-local.** No other game draws blind from a hand yet; it moves to `ui` when one does (as `rankName` moved to `kit`).
- **No Move history setting.** Nothing in the log is worth remembering: who holds the queen is hidden even from a perfect memory, apart from the giver, who knows it anyway.

## Deployment
- **Existing VPS alongside Laravel apps, behind nginx, Cloudflare proxied, run under Supervisor.** Already set up; one long-lived process with persistent disk fits in-memory rooms and SQLite. (nginx/Supervisor/Full-strict are assumptions to verify at deploy time.)
- **Each production client build carries an id (Vite stamps it into the bundle and `index.html`); the server sends it in `session`, and a tab running a different build reloads once (guarded per tab in sessionStorage).** After a deploy, open tabs reconnect with the old bundle, which may not understand new view shapes. Rooms don't survive the restart anyway, so the reload costs nothing; the guard stops a loop if a cache keeps serving the old bundle. Dev has no id and never reloads.
- **Updates run through `npm run deploy` (`scripts/deploy.sh`): fast-forward pull, frozen install, build, `supervisorctl restart`.** One command, no skipped build; fails fast on a diverged checkout or lockfile drift. Not `pnpm deploy`, which is pnpm's own built-in command.
- **The deploy builds the client into `apps/client/dist.next` and swaps it in only after the build succeeds; if `dist/` is missing anyway, page requests get a plain 503 "being updated".** Vite empties its outDir first, so building in place left the running server with no client whenever a build failed (a production outage: white screen, and an ENOENT path shown as an error).
- **Real client IP via configurable `TRUSTED_PROXY_HOPS` / `REAL_IP_HEADER` (`CF-Connecting-IP`).** Otherwise every IP-based limit sees Cloudflare's IPs; configurable for self-hosters.
- **Branding via `APP_NAME` / `APP_PRIMARY_COLOR`; nothing domain-specific hard-coded.** Ready for self-hosting later.
- **Docker and license deferred.** Pick the license deliberately (MIT vs AGPL) before open-sourcing.
